# SW 보고서 정정 반영 설명문

이 문서는 작품을 처음 접하는 독자를 위한 대체 설명이다. [정정·우선순위 문서](SW_REPORT_CORRECTIONS_AND_PRIORITY_20260916.md)의 각 항목을 본문에 사용할 수 있는 수준으로 풀어 썼다. 첨부 DOCX는 수정하지 않았다. 아래 페이지와 방정식 예시는 원리를 설명하기 위해 구성한 예시이며, 실제 교재를 촬영한 결과나 성능 측정값이 아니다.

## 1. 페이지 중간 표현과 수식 구조는 무엇이 다른가

사진에서 글자를 알아내는 것만으로는 책을 편하게 읽을 수 없다. 지문 다음에 어떤 수식을 읽어야 하는지, 선택지가 어디서 시작하는지 등의 관계도 필요하기 때문이다. 프로그램은 인식한 내용을 종류·위치·읽는 순서에 따라 정리한다. 이렇게 사진의 인식 결과와 최종 읽기 자료 사이에서 정보를 보관하는 형태를 **페이지 중간 표현(Page IR, Intermediate Representation)**이라고 한다.

다음과 같은 문제가 있다고 가정하자.

> 방정식 (x+1)²=9의 해를 구하시오.

페이지 중간 표현은 이 문제를 다음처럼 정리할 수 있다. 아래 표는 실제 저장 형식을 단순화한 설명용 표현이다.

| 내용 번호 | 종류 | 내용 | 페이지 안의 위치 | 읽을 순서 |
|---|---|---|---|---|
| A | 지문 | 다음 방정식의 해를 구하시오. | 문제의 위쪽 | 1 |
| B | 수식 | (x+1)²=9 | 지문 아래 | 2 |
| C | 선택지 | ① … ② … ③ … ④ … ⑤ … | 수식 아래 | 3 |

실제 자료에는 위치를 나타내는 좌표, 원문, 각 내용의 식별자, 문제 구성의 관계 등이 담긴다. 프로그램은 이러한 정보를 읽기 항목으로 바꾸므로, 사용자가 문제의 지문과 수식 등을 순서대로 탐색할 수 있다. Page IR 자체가 수식을 푸는 기능은 아니다.

한편 수식 B를 소리와 점자로 바꾸려면 ‘2가 무엇의 지수인가’를 알아야 한다. 이를 위해 수식 문자열을 해석하여 **수식의 구성 관계를 나타내는 나무 모양 구조(AST, Abstract Syntax Tree)**로 바꾼다.

```text
등호 관계 (Relation)
├─ 왼쪽: 거듭제곱 (Power)
│  ├─ 밑: 괄호 묶음 (Group)
│  │  └─ 덧셈 (Sum): 문자 x와 숫자 1
│  └─ 지수: 숫자 2
└─ 오른쪽: 숫자 9
```

이 구조를 보면 지수 2가 x만이 아니라 괄호 안의 x+1 전체에 적용된다는 것을 알 수 있다. 음성 생성은 이 관계에 한국어 읽기 규칙을 적용하고, 점자 생성은 같은 관계에 점역 규칙을 적용한다. 따라서 두 출력을 각각 원문 문자열에서 따로 추측하는 대신, 같은 수식 구조를 공통 출발점으로 사용할 수 있다. 다만 이 과정은 수식을 표현하는 작업이며 해를 계산하거나 정답을 확인하는 작업은 아니다.

**Page IR은 ‘페이지에 무엇이 있고 어떤 순서로 읽는가’를 정리하고, AST는 ‘개별 수식 안에서 기호들이 어떤 관계를 가지는가’를 정리한다.**

## 2. 문제 영역은 어떤 규칙으로 묶는가

글자 인식 결과에는 지문, 설명, 조건, 선택지 등이 함께 나타난다. 프로그램은 인식된 글에서 문제의 시작과 구성 요소를 알려 주는 표식을 찾고, 읽는 순서와 함께 검토하여 하나의 문제로 묶는다. 이때 사용하는 방법은 **교재에서 관찰한 특징을 이용한 판별 규칙(휴리스틱)**이다.

예를 들어 다음과 같은 규칙을 사용한다.

1. **문제 코드로 시작 위치를 찾는다.** `[26008-0011]`처럼 대괄호 안에 다섯 자리 숫자와 네 자리 숫자가 연결된 표식을 새 문제의 시작 후보로 삼는다. 이후 내용을 다음 문제 시작 전까지 살펴보면서 지문과 답안 구조가 갖추어졌는지 확인한다. 코드 하나를 발견했다고 나머지 내용까지 무조건 정상 문제로 확정하지는 않는다.
2. **여러 동그라미 번호가 함께 있으면 선택지 후보로 본다.** 인식된 한 줄 안에 ①~⑤ 표식이 네 개 이상 모여 있으면 선택지 줄을 찾는 단서로 사용한다. ① 하나는 설명의 항목 번호일 수도 있으므로 그것만으로 선택지라고 단정하지 않는다. 선택지를 나눈 뒤에도 다섯 항목이 제대로 구분됐는지 확인한다.

이 밖에 ‘보기’, ‘(가)’, ‘(나)’, 시험 출처 등의 글도 구성 요소를 구분하는 단서가 된다. 이는 글꼴이나 색깔로 확률을 계산한다는 설명과 다르다. 문서 인식 모델이 영역을 구분하는 단계와, 그 결과를 프로그램이 문제 단위로 다시 묶는 단계도 구분해야 한다. 이러한 규칙은 선정한 교재의 형식을 바탕으로 하므로 모든 교재에 동일하게 적용된다고 보장할 수 없다.

## 3. 페이지를 관측한 뒤 언제 전송하는가

카메라는 같은 책을 계속 촬영한다. 보이는 사진을 모두 저장하면 같은 페이지가 여러 번 들어가고, 한 번의 인식 오류를 페이지 넘김으로 받아들이면 사용자가 넘기지 않은 페이지까지 새 페이지로 저장할 수 있다. 따라서 프로그램은 **촬영하기 적합한가**, **이미 저장한 페이지인가**, **전송 결과가 실제 저장됐는가**를 나누어 확인한다.

### 3.1 페이지 번호를 한 번 읽는 것만으로 승인하지 않는다

프로그램은 책 아래쪽에서 인식한 왼쪽·오른쪽 문자열을 한 쌍으로 다룬다. 예를 들어 왼쪽에서 `26`, 오른쪽에서 `27`을 읽었다면 `(26, 27)`이 한 번의 관측 결과가 된다. 여기서 ‘좌우 문자열 일치’는 왼쪽 번호와 오른쪽 번호가 서로 같아야 한다는 뜻이 아니다. **지금 관측한 좌우 한 쌍이 이전에 저장한 페이지의 관측 쌍과 일치하는지**를 뜻한다.

| 확인 단계 | 현재 구현의 조건 요약 | 필요한 이유 |
|---|---|---|
| 촬영 후보 검사 | 페이지가 검출되고 영상 품질·움직임 안정성 등의 조건을 통과 | 페이지를 넘기는 손이나 불안정한 사진을 저장할 가능성을 줄임 |
| 유효 관측 수집 | 서로 다른 영상에서 좌우 문자열이 모두 나온 관측을 모음 | 한쪽을 못 읽은 결과나 같은 사진의 반복 계산을 새 근거로 세지 않음 |
| 같은 페이지 차단 | 저장이 확인된 페이지의 참조 관측과 한 번이라도 일치하면 같은 페이지로 판단 | 같은 내용을 새 페이지로 잘못 저장하는 일을 우선 억제 |
| 새 페이지 후보 판단 | 유효 관측 5개 이상, 기존 참조와의 일치 0개, 새 문자열 쌍이 최소 3회 일치 | 우연히 한 번 다르게 읽힌 결과를 새 페이지로 승인하지 않음 |
| 페이지 변경 확인 | 다른 페이지라는 식별 결과와 함께, 영상 변화의 안정적 확인 또는 일관된 숫자 쌍의 변화 근거를 요구 | 문자열의 불일치만으로 실제 페이지가 바뀌었다고 단정하지 않음 |
| 좌우 자료 준비 | 같은 원본 영상에서 좌우를 추출하고 두 쪽 모두 준비 검사를 통과 | 서로 다른 시점의 페이지가 한 펼침면으로 섞이거나 한쪽만 준비된 자료가 전송되는 것을 방지 |
| 저장 응답 확인 | 전송 대기 자료를 보존하고 서버의 저장 완료 응답을 확인 | 전송을 시도했다는 사실과 실제 서버 저장을 구분 |

첫 촬영에는 비교할 기존 페이지가 없지만, 여러 관측에서 결과가 일관되는지 확인하는 조건은 유지한다. 번호를 읽지 못하거나 제한 시간 안에 판단 근거가 모이지 않으면 ‘모름’으로 남기고 다시 관측한다. 시간 초과가 새 페이지 승인으로 바뀌지는 않는다. 이전에 저장한 페이지의 참조 기록도 용량이 제한된 목록이므로, 무제한의 전체 도서를 대상으로 중복을 영구 차단하는 기능으로 설명해서는 안 된다.

### 3.2 같은 페이지는 왜 한 번의 일치로 차단하는가

이 시연에서는 같은 페이지를 놓쳐 중복 저장하는 실수가, 다른 페이지를 잠시 보류하여 다시 관측하는 것보다 처리 결과에 더 큰 영향을 준다고 보았다. 이에 따라 새 페이지를 승인할 때는 여러 근거를 요구하되, 이미 저장한 페이지와의 일치를 발견하면 일찍 차단한다.

반복 관측이 도움이 되는 이유는 간단한 확률 예시로 설명할 수 있다. **실제로 같은 페이지일 때, 한 번의 유효 관측에서 참조와 일치하여 같은 페이지임을 알아낼 확률이 80%**라고 가정하자. 한 번 놓칠 확률은 20%이다. 각 관측이 서로 독립이고 성공 확률도 같다면, n번 모두 놓칠 확률은 다음과 같다.

**모두 놓칠 확률 = (1−0.8)ⁿ = 0.2ⁿ**

| 유효 관측 기회 | 모두 놓칠 확률 |
|---|---:|
| 1번 | 20% |
| 2번 | 4% |
| 3번 | 0.8% |
| 5번 | 0.032% |

즉 여러 번 가운데 한 번만 같은 페이지임을 알아내도 저장을 막는 방식은, 한 번의 인식에만 의존하는 것보다 중복 방지 기회를 늘린다. 같은 페이지라는 일치가 먼저 나오면 다섯 번을 모두 기다릴 필요도 없다.

다만 **80%는 설명을 위한 가정이며 측정된 성능이 아니다.** 같은 흐림이나 그림자가 계속 남으면 여러 영상에서 똑같이 잘못 읽을 수 있어 실제 관측은 독립적이지 않다. 참조에 잘못된 문자열이 남은 경우에도 이 계산을 그대로 적용할 수 없다. 따라서 0.032%를 실제 중복 전송률로 제시해서는 안 된다. 이 수치는 가정 아래에서 ‘같은 페이지라는 일치를 끝까지 발견하지 못하는 사건’만 설명하며, 실제 전송에는 새 관측의 일관성·페이지 변화·좌우 준비 등의 조건이 더 필요하다. 다른 페이지를 같은 페이지로 오인하는 확률도 이 계산으로 알 수 없다.

### 3.3 전송 완료와 읽기 자료 완성은 다르다

전송할 좌우 자료는 먼저 장치의 전송 대기 공간에 보존된다. 프로그램은 서버가 자료를 저장했다는 응답을 받은 뒤에 전송 완료를 안내하고, 해당 페이지를 중복 비교의 참조로 등록한다. 통신 오류로 같은 자료를 다시 보내더라도 같은 전송을 중복 저장하지 않도록 전송 식별자를 이용한다.

촬영을 마감하면 서버는 접수한 페이지를 인식하고 문서 구조와 읽기 자료를 완성한다. 이 자료가 읽을 수 있는 상태(READY)로 게시된 뒤에 자료 생성 완료를 안내한다. 따라서 ‘전송 완료’, ‘읽기 자료 완성’, ‘음성 재생 완료’, ‘실제 점자 돌출’은 서로 다른 결과이다. 하나의 신호만으로 나머지까지 성공했다고 판단하지 않는다.

## 4. 수식 해석 상태와 출력 제한

프로그램은 수식을 끝까지 해석했는지와 해석하지 못한 부분이 있는지를 구분한다.

| 상태 | 의미 | 처리 |
|---|---|---|
| 해석 완료(VALID) | 수식의 구조를 끝까지 해석함 | 지원되는 구조를 음성과 점자로 변환 |
| 일부 해석(PARTIAL) | 해석하지 못한 구조가 남음 | 불확실성을 안내하고 가능한 내용을 읽되, 수식 점자는 비움 |
| 해석 실패(INVALID) | 해석 오류나 처리하지 못한 기호가 남음 | 불확실성을 안내하고 수식 점자는 비움 |

이는 확실하지 않은 구조를 올바른 점자인 것처럼 전달하지 않기 위한 처리이다. 다만 해석 완료는 사진 속 글자를 정확하게 인식했다는 보장이 아니다. 잘못 인식한 수식도 문법상 해석될 수 있기 때문이다. 해석된 기호라도 점역에서 지원하지 않으면 점자를 표시하지 않을 수 있다. 상태 이름의 오기 `PARITAL`은 `PARTIAL`로 정정한다.

## 5. 점자 데이터가 모터 움직임으로 바뀌는 과정

점자 한 칸의 여섯 점은 왼쪽 세 점과 오른쪽 세 점으로 나누어 제어한다. 세 점에는 각각 올라옴과 내려감의 두 상태가 있으므로, 한쪽 열은 모두 내려간 상태부터 모두 올라간 상태까지 여덟 가지 조합을 가진다.

같은 길이의 제어 신호를 주어도 모터마다 실제 위치가 다르며, 신호 길이와 움직임이 단순한 비례 관계를 따르지 않을 수 있다. 하드웨어팀은 각 모터에서 필요한 상태를 만드는 신호의 길이, 즉 펄스 폭을 실측했다. 펌웨어는 점자의 좌우 조합을 해당 모터의 상태로 바꾸고, 측정표(LUT)에서 값을 골라 모터 제어 보드(PCA9685)에 전달한다.

따라서 모든 모터에 같은 각도 계산식을 적용한다는 설명은 현재 구현과 다르다. 실측은 하드웨어팀의 기여이며, 측정값 선택·논리적인 읽기 순서와 물리 채널의 연결·제어 신호 전송이 소프트웨어의 역할이다. 현재는 논리적인 첫 셀이 사용자의 왼쪽에 표시되도록 셀 순서 보정을 반영했다.

## 6. 점자 규정에 관한 설명

점역에는 한국 점자 규정을 참고하여 구현한 수학 기호의 표시 규칙을 사용했다. 수식 구조를 순서대로 살펴보며 필요한 기호와 구분 표지를 만들고, 장치에서 표시할 수 있는 점자 데이터로 변환한다. 현재 지원하는 기호와 구조를 대상으로 하며, 규정 전체의 모든 사례를 구현하거나 검수했다는 의미는 아니다.

편집 시에는 본문의 2017년 표기와 코드에 적힌 2024년 자료 출처를 대조하여 참고문헌의 연도·문서명을 확정해야 한다. 이 문서에서는 원본 참고문헌의 대조가 끝난 것으로 처리하지 않는다.

## 7. 사용할 사진은 어떻게 고르는가

사진 선택은 ‘조건을 만족하는 후보를 남기는 과정’과 ‘남은 후보 가운데 원본을 고르는 과정’으로 나뉜다. 먼저 페이지 검출과 기본 영상 조건을 검사하고, 책의 위치와 움직임이 안정적인지 확인한다. 그다음 조건을 만족한 후보들 사이에서 여백, 페이지 검출의 품질, 지나치게 밝거나 어두운 영역의 비율, 조명의 고른 정도, 선명도 등을 정해진 우선순위로 비교한다.

따라서 가장 선명한 사진만 고르는 과정으로 축약하면 실제 선택 기준을 충분히 설명하지 못한다. 빠른 판단에는 축소 영상을 사용하지만, 좌우 페이지를 만드는 데 필요한 원본 영상은 함께 보존한다. 선택된 같은 원본에서 좌우를 나눈 뒤 책의 휘어짐을 보정한다. 함수명을 적는다면 `selecr_best()`가 아니라 `select_best()`이나, 본문에서는 ‘최종 사진 선택’이라는 역할 설명을 우선한다.

## 8. 소프트웨어 기능은 네 단계로 설명한다

전체 기능은 ① 페이지 촬영과 이미지 보정, ② 글자 인식과 문서 구조 정리, ③ 음성 및 점자 데이터 생성, ④ 사용자 조작에 따른 읽기와 출력의 네 단계로 구성된다. 앞부분의 ‘세 가지’와 중복된 번호도 이 구성에 맞춰 정정한다.

사용자는 촬영 모드에서 새 자료를 만들고 페이지를 촬영한다. 촬영을 마감하여 읽기 자료가 완성되면 읽기 모드에서 자료를 선택한다. 이후 버튼으로 페이지와 항목, 수식의 표시 구간을 이동한다. 점자는 한 번에 10칸씩 표시하며, 현재 선택한 내용이 바뀌면 이전 음성을 중단하고 새 내용에 맞는 출력으로 전환한다.

## 9. 실제 시연 장치와 복구 기능

실제 시연에서는 라즈베리파이 4가 카메라와 버튼 입력을 받아 장치의 동작을 관리한다. 휴대폰의 Android IP Camera가 영상을 제공하고, 데스크톱 서버가 본문 인식·문서 처리·음성 파일 생성을 담당한다. 라즈베리파이는 받은 음성을 AUX 이어폰으로 재생하고, 블루투스를 통해 STM32에 점자 표시 데이터를 보낸다. 개발과 선행 검증에 사용한 Laptop을 최종 실행 장치로 설명하지 않는다.

전원이 들어오면 프로그램을 자동으로 시작하도록 구성했다. 같은 자료를 다시 선택할 때에는 서버에 저장된 장치별 읽기 위치를 불러온다. 일시적인 카메라 통신 단절에는 촬영 프로그램을 종료하지 않고, 재시도 간격을 최대 5초까지 늘리며 연결 회복을 기다리도록 했다. 인증 오류 등 다시 시도해도 해결되지 않는 오류는 별도로 처리한다. 이는 네트워크와 서버 없이도 작동한다거나 모든 종류의 고장에서 자동 복구한다는 뜻은 아니다.

## 10. 확인된 결과와 남은 한계

선정한 교재에서 페이지를 촬영하여 새 읽기 자료를 만들고, 라즈베리파이에서 물리 버튼으로 이동하면서 실제 음성과 점자를 출력하는 흐름을 확인했다. 부팅 후 자동 실행과 읽던 위치 복구, 카메라 연결을 끊었다가 되돌린 후 자료 생성 완료도 사용자 관측으로 확인했다. 카메라의 장기 단절 재시도 분기는 별도 모의 시험으로 검사했으며, 실제 단절 시험의 재시도 로그가 모두 확보된 것은 아니다.

촬영은 조명·초점·책의 배치에 영향을 받는다. 현재 Pi 시연은 페이지 식별 수집 제한 시간을 45초로 조정한 조건이며, 최초 촬영까지 수분이 걸린 사례도 있었다. 45초가 전체 촬영 또는 자료 완성의 시간 상한은 아니다. 따라서 ‘실시간 영상 사용’을 ‘즉시 인식·출력’과 같은 뜻으로 쓰지 않는다. 복잡한 수식·표와 미지원 기호에는 제한이 있고, 확인한 교재 이외의 전반적인 정확도나 학습 효과는 별도의 평가가 필요하다. 저장 중 강제 전원 차단에 대한 내구성도 완료된 읽기 상태의 복구 시험과 구분한다.
