# 보강 해설 배치 설계

입력: 완료된 [선정표](CORE_PRINCIPLES_SELECTION.md)와 [근거 카드·예제](CORE_PRINCIPLES_EVIDENCE_CARDS.md). 본문의 기존 한국어 설명과 용어표는 보존하고 아래 내용을 추가한다. 이 설계를 완료한 뒤 최종 해설 문장을 작성한다.

| 배치 | 목적·독자가 이해할 것 | 필요한 사실·도식·예제 | 제외 |
|---|---|---|---|
| §4 도입 | 프로젝트가 조합한 핵심 해결 방식과 그 기능적 효과를 개관 | K1–K5 요약표, 검증된 비교 우위와 구분 | 근거 없는 최고·일반화 주장 |
| §4.2 끝 | 왜 한 번 다른 문자열이 나온 것만으로 새 촬영을 허가하지 않는가 | K3a same/changed/inconsistent, accepted reference와 gate | threshold 변경 제안 |
| §4.3 끝 | 좌우 겹침과 같은 페이지 재촬영을 분리 | K3b conservative masks·내용 보존의 대가 | 겹친 본문 자동 제거를 구현한 것처럼 설명 |
| §4.4 끝 | 인식→문서 중간 표현→선택할 항목의 역할 분리 | K2 세 단계 표, 문제 멤버십 vs 순서, 원본 의미 누락 한계 | 인식 모델이 모든 의미를 추론한다는 설명 |
| §4.5 끝 | AST가 구조를 보존하고 두 출력에 쓰이는 이유 | K1 분수 AST 가지 도식, 표기 문자열/관계/출력 역할; 탐색은 item/span/window | AST 전체 의미계산, AST branch navigation 주장 |
| §4.6 끝 | 전송 재시도와 새 촬영의 중복을 구별 | K3c stable request identity와 response replay | exactly-once 전체 시스템 보장 |
| §4.8 끝 | 저장된 위치와 현재 출력 권한의 차이 | K5 응답 유실·같은 명령 ID replay·늦은 음성 취소 | 강제 취소·physical 적용 보장 |
| §6 끝 | 각 검사가 없을 때의 위험과 통과 의미 이해 | K4 검사→막는 실패→한계 표 | 새 product mutation 또는 사고 원인 확정 |
| §7 추가 | 동일 입력의 변환과 작은 반례를 직접 확인 | K2 뒤섞인4영역→4focus, K3 rawpair3패턴, K1 partial/invalid, bbox누락schema통과 | H1 실제 이미지 결과와 synthetic 예제 혼합 |

문장 구성은 ‘사용자 문제→왜 앞 단계 결과만으로 충분하지 않은가→현재 처리→구체 결과→한계→코드 근거’ 순으로 한다. exact identifier는 기존 대응표나 원시 예제로 연결한다. 영어로 개념을 대체하는 서술로 되돌리지 않는다.

검증 계획: 작성 후 우선 오류·과장·누락 목록을 기록하고 그다음 교정한다. 도식은 기존4개+AST1개를 실제 렌더링한다. 기존 본문이 삭제되지 않았는지, 용어 대응표와 source/test 링크가 유지되는지, 247개 source hash가 동일한지도 확인한다.

완료: 배치·근거·도식·제외 범위 결정. 다음 단계는 본문 추가와 별도 검증보고서다.
