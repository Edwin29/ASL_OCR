# 처음 읽는 독자를 위한 SW 보고서 정정 사항과 수록 우선순위

이 문서는 첨부 최종보고서의 설명 수준을 기준으로, 사실관계를 바로잡을 부분과 내용을 보강할 순서를 정리한다. 대상 독자는 작품을 처음 접하며 소프트웨어 전공 지식이 많지 않은 사람이다. 기존 DOCX는 수정하지 않았다. 아래 예문은 향후 반영을 검토할 대체 설명이다.

판정 근거와 구현 위치는 [기존 점검표](PROTOTYPE_REVIEW_AND_SW_REPORT_ITEMS_20260916.md)에 둔다. 최종 본문에서는 한국어 역할을 먼저 설명하고, 필요할 때만 원래 용어를 괄호에 붙이는 방식을 권한다.

## 1. 사실관계 정정

### 1.1 페이지 전체를 정리하는 구조와 수식을 정리하는 구조를 구분한다

**현재 설명의 문제:** Page IR과 AST가 같은 종류의 문서 구조인 것처럼 이어진다. 독자는 페이지 전체가 하나의 수식 트리로 바뀐다고 이해할 수 있다.

**대체 설명 후보:**

> 인식 결과에는 지문, 수식, 표처럼 서로 다른 종류의 내용이 섞여 있다. 프로그램은 먼저 각 내용의 종류와 위치, 읽을 순서를 페이지 단위로 정리한다. 이를 페이지 중간 표현(Page IR)이라고 한다. 수식은 별도로 분자와 분모, 밑과 지수처럼 구성 요소 사이의 관계를 정리한다. 이 수식 구조를 AST라고 하며, 음성과 점자를 만드는 데 공통으로 사용한다.

설명 예시는 ‘한 문제의 지문·수식·선택지를 정리하는 것’과 ‘그 안의 수식 구조를 정리하는 것’을 나란히 놓는 정도면 충분하다. 실제 데이터 항목이나 클래스 구조까지 나열할 필요는 없다.

### 1.2 문제 분류를 폰트·색상에 따른 확률 판단으로 설명하지 않는다

**현재 설명의 문제:** 글자의 색·글꼴·위치로 문제 영역의 확률을 계산한다는 서술은 현재 문제 단위 분류 코드와 다르다.

**대체 설명 후보:**

> 프로그램은 인식된 글에서 문제 코드, 시험 출처, ‘보기’, ‘(가)’, ‘①~⑤’와 같은 표식을 찾는다. 이러한 표식과 읽는 순서를 이용해 지문, 조건, 보기, 선택지를 하나의 문제로 묶는다. 이렇게 묶인 내용은 사용자가 버튼으로 하나씩 선택해 읽을 수 있도록 정리한다.

OCR 모델의 영역 구분과, 인식된 글을 프로젝트 코드가 문제 단위로 묶는 처리는 별개다. 이 차이만 설명하면 되며 정규식 문법을 본문에 넣을 필요는 없다. 특정 교재의 표식에 의존하는 규칙이므로 모든 문제집에서 같은 결과를 보장한다고 쓰지 않는다.

### 1.3 ‘다음 페이지를 관측함’과 ‘전송 완료’를 구분한다

**현재 설명의 문제:** 28/29가 반복 관측되면 계속 전송되고 있음을 판단한다는 문장은, 번호를 읽은 순간 전송까지 완료된 것처럼 보인다.

**대체 설명 후보:**

> 같은 페이지를 여러 번 저장하지 않도록 왼쪽과 오른쪽 페이지 번호의 인식 결과를 함께 비교한다. 예를 들어 26/27을 전송한 뒤 28/29가 여러 영상에서 반복해서 관측되면 다른 페이지일 가능성을 판단할 수 있다. 프로그램은 여기에 영상이나 페이지 번호의 변화 조건을 함께 확인한 뒤 다음 촬영을 진행한다. 전송 완료는 촬영 결과가 서버에 저장됐다는 응답을 받은 후에 안내한다.

‘한 번 다르게 읽혔으니 바로 다음 페이지’라는 방식이 아니라는 점이 핵심이다. 본문에는 이 원리를 설명하고 N/K 등 세부값은 필요할 때만 작은 표로 넣는다.

### 1.4 수식 해석 상태와 인식의 정확성을 구분한다

**현재 설명의 문제:** 일부만 해석한 경우와 해석에 실패한 경우를 모두 INVALID라고 부른다. 해석 완료를 원문 인식이 정확하다는 뜻으로 오해할 여지도 있다.

| 상태 | 독자에게 설명할 의미 | 출력 |
|---|---|---|
| 해석 완료(VALID) | 프로그램이 수식의 구조를 끝까지 해석함 | 지원되는 구조를 음성·점자로 변환 |
| 일부 해석(PARTIAL) | 처리했지만 해석하지 못한 구조가 남음 | 불확실성을 알리고 해석 가능한 내용을 읽음. 수식 점자는 비움 |
| 해석 실패(INVALID) | 오류가 있거나 처리하지 못한 기호가 남음 | 인식이 불확실하다고 안내하고 수식 점자는 비움 |

**추가할 설명 후보:**

> 수식 구조를 해석했다는 것은 사진 속 수식을 정확히 읽었다는 보장과는 다르다. 또한 해석된 기호라도 점역 기능에서 지원하지 않으면 점자를 표시하지 않을 수 있다.

`PARITAL`은 `PARTIAL`로 바로잡는다. 이 표는 세부 오류 코드 없이도 불완전한 결과를 제한하는 이유를 전달할 수 있다.

### 1.5 모터 제어를 실제 측정값에 맞게 설명한다

**현재 설명의 문제:** 목표 각도를 계산해 모든 모터를 같은 방식으로 움직이는 것처럼 읽힐 수 있다. 현재 펌웨어는 모터별로 측정한 신호값을 사용한다.

**대체 설명 후보:**

> 점자 한 칸의 여섯 점은 왼쪽 세 점과 오른쪽 세 점으로 나누어 제어한다. 각 세 점은 올라오거나 내려온 조합에 따라 여덟 가지 상태를 가진다. 같은 제어 신호를 주더라도 모터마다 실제 움직임이 다를 수 있어, 하드웨어팀은 모터별로 각 상태에 필요한 신호의 길이를 측정했다. 프로그램은 이 측정표에서 필요한 값을 찾아 모터 제어 보드로 보낸다.

처음에는 ‘신호의 길이’로 설명하고 필요하면 ‘펄스 폭’이라는 용어를 병기한다. 펄스 측정은 하드웨어팀의 작업, 측정표 선택과 전송은 소프트웨어의 작업으로 구분한다.

### 1.6 점자 규정의 출처를 확인한다

**현재 설명의 문제:** 본문에는 2017 규정이 적혀 있지만 현재 점역 코드는 2024 자료를 구현 출처로 명시한다.

**정정 방향:** 실제 사용한 원본과 참고문헌을 대조해 연도·문서명을 확정한다. 코드 주석 확인만으로 규정 전체를 검수했다고 표현하지 않는다.

**출처 확정 전 사용할 설명 후보:**

> 점역에는 한국 점자 규정을 참고해 구현한 수학 기호의 표시 규칙을 사용했다. 현재 프로그램에서 지원하는 기호를 대상으로 점자를 생성하며, 지원하지 않는 경우에는 불완전한 점자를 표시하지 않도록 했다.

이는 참고문헌 확인을 생략하자는 뜻이 아니다. 연도와 고시번호는 본문 흐름보다 참고문헌에서 정확하게 정리하는 편이 읽기 쉽다.

## 2. 설명을 정확하고 쉽게 만드는 보완

### 2.1 후보 제외와 최종 사진 선택을 나눈다

**대체 설명 후보:**

> 먼저 페이지가 너무 작게 보이거나 대비가 부족한 영상은 제외한다. 남은 영상에서도 책과 카메라의 움직임이 안정적인지 확인한다. 조건을 만족하는 여러 영상 중에는 여백, 페이지가 잘 구분되는 정도, 조명의 고른 정도와 선명도 등을 비교해 사용할 원본을 선택한다.

조건을 통과하는 과정과 그중 하나를 고르는 과정이라는 두 단계로 설명한다. `threshold`는 ‘판단 기준’, `select_best()`는 ‘최종 사진 선택’으로 표현하면 된다. 함수명을 유지한다면 `selecr_best()` 오기도 수정한다.

### 2.2 기능 구성을 네 단계로 일치시킨다

현재 본문은 ‘세 가지’라고 시작하지만 네 단계를 설명한다. 기존 흐름을 유지하려면 다음처럼 정리하는 것이 자연스럽다.

1. 페이지 촬영과 이미지 보정
2. 글자 인식과 문서 구조 정리
3. 음성 및 점자 데이터 생성
4. 사용자 조작에 따른 읽기와 출력

마지막 소절의 중복된 ‘3.’도 ‘4.’로 맞춘다.

### 2.3 Pi의 현재 역할과 복구 기능을 추가한다

**대체 설명 후보:**

> 실제 시연에서는 라즈베리파이가 카메라 영상과 버튼 입력을 받아 장치의 동작을 관리한다. 본문 인식과 음성 파일 생성은 연결된 데스크톱 서버가 담당한다. 라즈베리파이는 전원이 들어오면 프로그램을 자동으로 시작하며, 같은 자료를 다시 선택하면 서버에 저장된 읽기 위치를 불러온다. 일시적인 카메라 연결 끊김에는 촬영 프로그램을 종료하지 않고 다시 연결을 시도하도록 했다.

‘독립형 장치’나 ‘자동 복구’라고만 쓰면 서버가 필요 없거나 모든 오류에서 스스로 복구한다고 오해할 수 있다. 필요한 외부 구성과 확인한 복구 범위를 함께 설명한다.

### 2.4 지원 범위와 실제 확인 결과를 명시한다

**대체 설명 후보:**

> 선정한 교재를 촬영해 읽기 자료를 만들고, 물리 버튼으로 이동하면서 음성과 점자를 출력하는 동작을 확인했다. 다만 촬영 결과는 조명과 배치의 영향을 받으며, 일부 복잡한 수식과 표는 지원에 제한이 있다.

‘실시간’은 계속 들어오는 영상을 사용한다는 의미로 한정한다. 즉시 읽기 자료가 완성된다는 표현은 피한다. 회귀검사 개수는 소프트웨어 동작 확인의 근거이며 OCR 정확도나 실제 사용자 만족도 수치가 아니다.

## 3. 핵심 수록 후보의 중요도

중요도는 ‘이 내용이 없으면 처음 읽는 사람이 작품의 목적·동작·성과를 잘못 이해하는가’와 ‘이 작품이 채택한 해결 방법을 보여주는가’를 기준으로 정했다. **중요도 순서와 본문 배치 순서는 다르다.** 본문은 촬영부터 출력까지의 흐름을 유지한다.

### 1순위 — 반드시 충분히 설명

| 순위 | 내용 | 중요 이유 | 권장 표현 |
|---|---|---|---|
| 1 | 전체 시스템과 역할 분담 | 무엇을 입력받아 무엇을 출력하는지 알아야 뒤의 알고리즘을 이해할 수 있음 | 전체 흐름도 1개와 짧은 설명 |
| 2 | 수식 구조에서 음성과 점자 생성 | 단순 글자 읽기를 넘어 수식의 관계를 두 출력으로 전달하는 핵심 원리 | 방정식 1개로 LaTeX→AST→출력 예시 |
| 3 | OCR 결과를 읽기 단위로 정리 | 사진의 글자가 어떻게 지문·수식·선택지로 나뉘어 탐색되는지 설명 | Page IR과 읽기 항목을 작은 예시로 비교 |
| 4 | 촬영 모드·읽기 모드와 실제 조작 | 사용자가 작품을 어떻게 쓰는지 이해하는 데 필수 | 기본 사용 순서와 핵심 버튼 표 |
| 5 | 검증 결과와 한계 | 구현한 것과 목표만 세운 것을 구분하고 작품의 완성 범위를 제시 | 실제 조건·결과·남은 제약 표 |
| 6 | 페이지 식별과 중복 촬영 억제 | 연속 촬영에서 같은 내용을 반복 저장하지 않는 프로젝트의 주요 판단 방식 | 26/27→28/29 사례 |

### 2순위 — 핵심 원리를 뒷받침하되 분량을 조절

| 순위 | 내용 | 중요 이유 | 권장 표현 |
|---|---|---|---|
| 7 | 촬영 시점 선택과 좌우 분리·보정 | 입력 영상의 상태가 후속 인식에 영향을 주는 이유를 설명 | 실제 원본→좌우→보정 그림 |
| 8 | 불확실한 수식의 출력 제한 | 지원하지 않는 결과를 확실한 점자로 보여주지 않는 정책 | 상태 3종 표와 이유 2~3문장 |
| 9 | 전송 완료와 자료 생성 완료 | ‘보냈다’와 ‘읽을 수 있다’의 차이 및 자료 보존을 설명 | 저장 응답→처리→READY의 짧은 흐름 |
| 10 | 점자 10칸 표시와 모터 연결 | 논리적인 점자 데이터가 실제 돌출로 바뀌는 지점을 설명 | 한 칸의 좌우 상태와 실측표 연결 그림 |
| 11 | 현재 읽기 내용에 맞는 음성·점자 | 빠르게 이동할 때 이전 음성이 남지 않도록 하는 동작을 설명 | ‘재생 중 다음 항목으로 이동’ 사례 |
| 12 | 부팅·읽기 위치·카메라 복구 | 실험용 프로그램에서 실제 시연 장치로 이어진 완성도를 보여줌 | SW 말미 요약, 문제 해결 장에서 상세 설명 |

### 3순위 — 본문을 방해하지 않도록 압축

| 순위 | 내용 | 처리 방식 |
|---|---|---|
| 13 | 문제 구성 분류의 세부 규칙 | 1순위 문서 구조 설명에 핵심 표식만 포함. 정규식·모든 예외는 부록으로 이동 |
| 14 | 기술 스택·API·통신 필드·수치 | 각 기술의 역할을 표로 정리. API 약어, 전체 FRAME 문법, 해시, 함수명, timeout 세부값은 필요한 것만 본문에 남김 |

이 표는 앞선 수록 후보 16개를 독자 관점에서 묶은 것이다. 촬영/읽기 모드는 탐색 설명과, 사진 선택은 좌우 보정과 결합했다. 낮은 순위는 구현의 중요성이 낮다는 뜻이 아니라 **처음 읽는 독자에게 필요한 상세 분량이 적다**는 뜻이다.

## 4. 권장 본문 순서와 분량 배분

1. 전체 흐름 및 장치별 역할
2. 촬영 판단·페이지 변경·좌우 보정
3. 문서 인식·문제 구성·읽기 항목
4. 수식 AST·음성·점역·불확실성 처리
5. 사용자 탐색·10칸 출력·HW 연결
6. 실제 검증 결과·배포와 복구·제약

가장 많은 설명과 대표 예시는 **수식 AST와 두 출력**, **문서 인식 결과가 읽기 항목으로 바뀌는 과정**에 배정한다. 사진 선택과 페이지 변경은 실제 촬영 그림으로 설명을 줄일 수 있다. 전송·부팅·재연결은 사용자에게 보이는 동작과 결과를 먼저 적고 세부 구현은 문제 해결 장이나 부록으로 옮긴다.

마지막 검증 절은 반드시 남긴다. 분량이 부족하면 라이브러리 목록과 통신 필드를 줄이고, 실제로 어디까지 동작했는지와 어떤 조건이 필요한지를 보존한다.

외부 제작 기간·비용·교육효과 수치는 별도 문헌 확인 대상이다. 이번 정정 정리는 기술적인 사실과 설명 수준에 한정하며, 해당 수치나 첨부 본문은 변경하지 않았다.
